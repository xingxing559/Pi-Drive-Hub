# Windows 桌面界面与下载改进（本地开发版）

本次只修改仓库根目录的 Windows Flutter 应用；`mac/` 是独立 Flutter 包，未迁移这些功能。
所有开发和测试在 Linux 本地 box 上完成，未使用云端编码代理、未使用用户电脑，未访问真实网盘账号。

## 使用

- 宽窗口左侧提供「全部文件 / 传输中心 / 设置」，窄窗口保留顶部入口；文件行右侧直接下载，顶部「多选文件」用于批量下载。
- 「设置 → 默认下载目录 → 更改目录」调用已有 `file_picker` 系统选目录窗口，保存后应用于新任务；「恢复默认」回到系统下载目录下的 `PI Drive Hub`。
- 配置独立写入系统 application support 目录的 `download_settings.json`，不包含账号凭据。写入前检查可写性，写入失败保留旧设置，损坏配置提示并回退默认目录。
- 文件夹行的下载按钮或菜单「下载整个文件夹」都会递归加入队列；包含空目录。批量选择支持混合文件/目录，父子重复选择只下载一次。
- 扫描时可继续操作界面并停止扫描；停止不会取消已加入队列的文件。当前目录请求最多等待两分钟，停止在该请求结束后生效。
- 传输中心显示本地目标路径、进度和失败原因，支持单文件暂停/继续/失败重试。设置改变不会移动已有队列的目标文件。

## 下载行为和安全边界

- 百度 `start/limit`、夸克分页、123 `Page/next` 完整翻页；重复页与分页异常明确报错，不静默当作成功。
- 逐目录异步扫描；文件交给原下载管理器，普通账号默认 1 并发，SVIP 最多 8 并发任务，继续遵循原有服务端速度限制。
- 标准文件名和相对目录结构保持不变。Windows 非法字符替换为 `_`，保留设备名加 `_` 前缀，过长名称缩短。
- 本地同名文件/文件夹（含大小写冲突）加 `(1)`、`(2)` 编号，不合并已有目录、不覆盖已有文件。排队目标也参与去重。
- 拒绝 `.`、`..`、嵌入分隔符、异常远端子路径；检查本地 containment 与子目录符号链接/联接，写入前再检查目标是否存在。
- 不是操作系统沙箱：无法对抗其他进程在检查和实际写入之间主动替换目录/文件的竞态。请使用自己控制的下载目录，不要让其他程序同时改动它。
- 扫描上限：128 层、100,000 项；过大或不可读子目录会在错误汇总中显示。已成功加入的文件继续传输，失败目录可重新下载。
- 设置持久化；传输队列仍保持原项目的内存队列设计，不支持应用重启后恢复队列，也未新增文件夹级暂停/重试。

## 验证

环境：Flutter 3.38.3 / Dart 3.10.1，Linux x64。`pubspec.lock` 内 Flutter 测试依赖由该 SDK 解析更新；应用直接依赖只新增原已间接使用的 `path`。

```sh
flutter pub get
flutter analyze --no-pub
flutter test --no-pub --reporter expanded
```

结果：静态分析无问题，31 个测试通过。覆盖：

- 设置保存/重读/恢复默认/损坏回退/写入失败与目录选择取消；
- 百度 HTTP Mock 的第二页及第二页报错、夸克缺失 total 元数据、123 数字游标；
- 递归、空目录、父子去重、大小写和非法名冲突、已有文件不覆盖；
- 非法远端路径、链接目录、部分列举失败、扫描取消、切换账号；
- 下载失败重试、暂停/快速继续、删除运行任务和切换账号后的并发槽位；
- 宽/窄窗口、浅/深色界面无溢出、设置导航与点击文件夹下载的离线 UI 集成。

`mac/` 有独立 pubspec；原仓库根目录分析会错误地把 mac 测试解析到 Windows 包，并报 61 个跨包问题。本次在根 `analysis_options.yaml` 排除 `mac/**`，不是修改或宣称修复 mac 项目。

可选：导出真实 Flutter 控件的离线渲染截图（Mock 文件/账号，不是 Windows 原生运行截图）：

```sh
PI_UI_FONT=/path/to/NotoSansCJK-Regular.ttc \
PI_UI_CAPTURE_DIR=/tmp/pi-drive-ui \
flutter test test/desktop_ui_test.dart --no-pub
```

字体路径与导出目录只用于测试，不影响发行应用。测试不读取真实账号、cookie、令牌，也不发真实网盘请求。

## Windows x64 测试兼容性修复

- 使用官方校验过的独立 Linux SDK Flutter 3.44.7 / Dart 3.12.2（与 Windows CI 相同），未改共享旧 SDK。
- 在改代码前，用此 SDK 复现了原有 3 个 UI 测试的 `ListTile` / `ColoredBox` 断言；替换列表背景 `Container` 为 `Material` 后消失。没有忽略异常或删除测试。
- `DownloadManager.add` 现在是需要等待的异步入队方法：先解析用户选择的目录别名，捕获 canonical 根目录，再加入队列；`FolderDownload` 相应等待入队。账号在解析期间切换时拒绝旧任务。
- canonical 根目录在排队后保持不变，任务启动和清理前再次核验，根目录被换成链接时不能重新绑定到新目标；子目录的链接/联接、越界路径仍被拒绝。
- 新增可注入路径解析器和 Windows 路径上下文的回归测试：8.3 别名、驱动器大小写和分隔符、长路径前缀、UNC、不同盘符、相似前缀、`..`、相对根路径、内部/外部 junction 及根目录替换；另有真实本地链接和排队后替换测试。
- 测试临时目录和目标目录统一 canonical；FakeDrive 提供实际进入下载的启动事件，替代固定 20ms 暂停。等待保留 10 秒有界超时，失败附带任务状态、错误和路径，便于 Windows 排查，不是无限等待或放宽预期。
- 新 SDK 下 `flutter analyze --no-pub` 无问题，完整 `flutter test --no-pub --reporter expanded` 共 40 项通过。所有原 31 项仍执行，没有 skip。
- 本地复现了 UI 原因及路径别名导致旧检查误拒绝的机制，但没有 Windows 本机；原日志没有实际 short/long 路径对照，具体路径别名种类仍需由新的 x64 CI 证实。Linux 上的 Windows 风格注入测试不等于原生 Windows 验证。
- 未修改 `.github/workflows/build-windows.yml`；授权后触发它仍会运行 x64 和 ARM64 矩阵。目标 x64 制品是包含 exe 和依赖的 ZIP，不是 MSI/安装向导。
